Dev Log - 2026-07-13

Summary

contract hardening and provenance hygiene day

Today was about tightening the boundary between observation and authority. The main work added two local-only collectors: one for canonical evidence identity and one for runtime identity. Both are deliberately conservative. They now surface enough structure to support later manifest work without pretending that hostname, filename, or a successful script run is the same thing as canonical proof.

The other half of the day was security cleanup with history attached. Preview credentials were removed from the example env, and the credential-rewrite / LFS recovery path was documented in a way that can be audited later instead of reconstructed from memory and hope. The day did not produce live runtime proof. It produced better truth surfaces, better failure edges, and less room for accidental overstatement.

What I completed

Canonical evidence identity hardening

- Added `scripts/audit/collect_canonical_evidence_identity.py` and tests.
- The collector now separates machine authority from repository identity instead of blending them together.
- Explicit canonical-machine assertion is required; provisional or inconsistent inputs fail closed.
- Output stays deterministic, redacted, and side-effect free.

Canonical runtime identity hardening

- Added `scripts/audit/collect_canonical_runtime_identity.py` and tests.
- The collector derives a stable runtime identity from supported-profile bytes, selected Compose files, and migration metadata.
- It fails closed on missing services, ambiguous Compose paths, invalid service identities, multiple migration heads, and dangling migration parents.
- It remains static observation tooling only. It does not contact Docker or assert service health.

Security containment and proof notes

- Removed committed preview credentials from `.env.private-preview.example`.
- Wrote documentation for the credential history rewrite rehearsal and the LFS-safe recovery path.
- Added proof notes for LFS payload preservation, missing payload recovery, and ref reconciliation.
- Tightened canonical evidence validator CI inputs and fixture cleanup so the audit path stays internally consistent.

Important outcome

The system stopped treating “I can observe something” as equivalent to “I can certify it.” That matters because the collectors now tell the truth about their own limits. They are useful, but they are not authority. That distinction is the whole game in this part of the stack.

The security work moved in the same direction. The credential rewrite path is no longer just an incident trail in a terminal session. It is documented as a recoverable sequence with payload integrity preserved and the missing pieces named explicitly. That is not polish. It is drift prevention.

Narrative Log

Dev Log - 2026-07-13

This was a truth-alignment day more than a feature day. The work kept circling the same problem from different angles: the system needs to distinguish observation from authority, and it needs to do that without making the operator guess. That led to two new local collectors. One now captures canonical evidence identity. The other captures runtime identity from supported profiles, Compose definitions, and migration metadata. Both are bounded. Both are static. Both are honest about what they cannot prove.

The evidence collector set the tone early. It no longer treats repository state and machine state as interchangeable. Explicit canonical-machine assertion is required, and the tests now make that boundary visible. The runtime collector pushed that same discipline deeper into the supported-profile and migration seams. It hashes what matters, rejects ambiguous Compose paths, fails closed on missing or conflicting migration heads, and refuses to imply live Docker or health-state proof. That mattered because the repo now has a way to describe itself without sneaking authority in through the back door.

The rest of the day was less about building new surface area and more about cleaning up a real security path so it can be reasoned about later. Preview credentials were removed from the example env. Then the credential history rewrite and LFS recovery path were documented in stages: rehearsal, safe rewrite proof, payload preservation, missing payload recovery, and ref reconciliation. That sequence matters. It turns an incident response into a record that can be reviewed instead of rediscovered. The LFS fixture cleanup and validator input fixes fit the same pattern. They are small, but they keep the proof path from drifting under the feet of the next person who has to trust it.

The deeper change is simple: the system is starting to keep its own promises more narrowly. The collectors are local-only and observation-only. The docs are explicit about that. The security notes are exact about what was recovered and what was merely recorded. Nothing here is flashy, and that is the point. A system that can distinguish provisional observation from accepted truth is a system that can keep growing without lying to itself.

That is what today bought: less ambiguity, better failure modes, and a cleaner path to the next proof slice.
