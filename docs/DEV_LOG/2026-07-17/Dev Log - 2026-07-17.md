Narrative Log

Dev Log - 2026-07-17

This was a day of making a hybrid boundary stop lying about itself. The friends-family tester lane had become a split system: one cloud model, one local model, and enough surrounding code that the old generic “local” framing was no longer good enough. The work today made that split explicit instead of implicit.

The first correction was in the supported profile and provider machinery. DeepSeek stayed the cloud default, but the profile now allows exactly one cloud model and one Whoosh’d-selected local model. That policy was carried through the backend catalog, provider resolution, validation logic, tests, and operator docs. The point was not to add options. It was to make the allowed options visible and enforceable. A system like this gets fragile when the policy lives only in the operator’s head or in a comment that no one reads twice.

The second correction was the health surface. The cloud-provider health path no longer returns a stub degraded status; it probes the endpoint. That is a small change with a large effect on trust. A health endpoint that tells the truth, even when the answer is inconvenient, is worth more than one that always looks tidy. Tidy is often how drift starts.

The third correction was the interface. The frontend now calls the local provider Whoosh’d in badges and selectors instead of flattening it into “local.” That is not cosmetic. It is the difference between a UI that mirrors the runtime and a UI that teaches the wrong model of the system. When a tester sees Whoosh’d, they know which lane they are standing in.

The operational work followed the same pattern from a different angle. A branch-local launchd plist and keepalive script now try to reconcile the guest server after login: open Tailscale, wait for Docker Desktop, verify Whoosh’d, check `.env.tester`, and bring up the tester compose stack. That is not live proof, and it should not be mistaken for one. It is recovery scaffolding. But it matters because the system is starting to encode the boot sequence as something repeatable instead of something fragile and remembered.

The deeper shift is simple: the guest lane is becoming legible enough to operate without guesswork. Policy is clearer, the UI names the actual runtime, health probes are more honest, and the recovery path is moving toward something the machine can help with. That is what drift prevention looks like when it is working.
