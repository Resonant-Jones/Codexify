architecture truth-alignment day

Today was about making two boundaries explicit: how Axis is entered and how supported Compose observations become receipts. The first half of the day turned the Axis role into a documented invocation and reasoning interface instead of an implicit instruction set. Narrative Log

Dev Log - 2026-07-15

This was a day of boundary-setting, and that made it useful. The work did not add a flashy new capability. It made the repo more exact about three things that tend to blur together if nobody names them: the Axis mode, the live supported-Compose observation path, and the guest model boundary for the friends-and-family tester profile.

The Axis work came first. The repo now has a portable reasoning interface and an invocation protocol, plus a character directive and supporting node docs. That seems modest until you look at what it fixes underneath: the system no longer has to rely on ambient interpretation for when it is speaking as Axis, what source set it should consult, or how continuity should be interpreted. That matters because once a role becomes part of the operating surface, it stops being decoration and starts being an interface.

The live-proof receipt work sits in a different part of the stack, but it is solving the same class of problem. Codexify can now observe one already-running supported Compose project and emit a receipt that binds machine identity, static runtime identity, Docker state, and a fixed probe suite. The important part is what it does not do. It does not become canonical evidence by itself. It does not promote anything. It does not collapse live observation into release truth. That is the right kind of restraint. The system needs a way to record live state without turning every observation into a coronation.

The tester work pulls the same thread down into guest access. The friends-and-family profile no longer reads like a generic local-model browser with a friendly name. It now carries a single configured model boundary. The backend, provider registry, and catalog all align on that boundary, and the tests make the failure cases explicit. If the configured model is missing, the catalog degrades. If the request points at another model or provider, it gets rejected. That is more honest than discovery-by-accident, and it is easier to reason about when something breaks.

The deeper change is simple. The repo is becoming more explicit about what is policy, what is observation, and what is authority. That distinction is the whole game in a system that wants to stay local-first, permissioned, and resistant to drift. Today’s work did not add more surface area than necessary. It reduced the number of places where the system could quietly mean two different things at once.
