# Narrative Log - 2026-07-25

This was an observability and automation contract day. The work was about making the system explicit about what it knows, what it can decide, and what it must refuse to infer.

The campaign control plane became more concrete through parser hardening and tests. Marked new-file entries now normalize correctly, and the evaluator has clearer outcomes for lineage, checks, requested changes, branch state, scope, privacy, and merge authority. It can produce a stable receipt, but it still cannot dispatch an agent or merge anything. The control plane has a decision surface without becoming decision authority.

The larger slice was account observability. Invite links now have a lifecycle, hashed bearer tokens, generic public failure behavior, first-touch guest lineage, and registration attribution. Presence was kept intentionally narrow: a foreground heartbeat is the signal, not normal API traffic. The service accepts trusted account or server-issued guest context, creates or refreshes a bounded session, and uses explicit active and idle windows.

Retention turns those rules into deterministic cleanup receipts with dry-run support and safeguards around converted guests. The privacy tests define what the system refuses to collect as much as what it records.

The deeper shift is that operational state is becoming declared state. A campaign result is not eligible merely because a pull request looks healthy. An account is not present merely because a request arrived. Both domains now have contracts that make ambiguity visible and give operators a bounded place to investigate it.

The next step is live validation against local Compose and real database state. The code and focused tests establish structure, but they do not yet prove scheduled cleanup, deployment wiring, or final authorization behavior in a running environment.
