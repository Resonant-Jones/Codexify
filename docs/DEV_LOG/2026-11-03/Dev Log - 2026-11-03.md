The stock migrator defect is still open on `main` — the bind mount cannot carry the `backend/migrations` symlink across the mount boundary, so a stock-launched stack serves an application against a schema behind it. What changed today is the *instrumentation* around it.

- **Migrator outcome verification** (`5fe4aaf34`) — a new `verify_migration_outcome` step. A migration is confirmed only when the intended migrator container is identified unambiguously, has reached an exited terminal state with exit code zero, and the project's own database reports exactly one `alembic_version` row equal to the expected head. The script's own header states the rule plainly: it never declares a migration successful on the strength of a container's exit code alone.

- **Limits of a verified launch declared** (`974a508f3`) — an attached run never reaches outcome verification, because the run does not stop; a verified qualification run must use `--detach`. Untracked files enter the image in a way the source-specific tag does not describe, so a release qualification must use a clean checkout.

## Important outcome

The day's real shift was in where trust is allowed to come from. Three separate seams started refusing to accept a claim on assertion alone.

A migration is no longer "the container exited zero." It is "this container, exited zero, and this project's database now reports exactly the expected Alembic head." A generated projection is no longer "it was committed." It is "regenerating at the revision and timestamp recorded inside the artifact reproduces the committed bytes exactly." A coding run is no longer "a worker said it started." It is a database-conditional claim with a unique constraint, an owner, a heartbeat, and a terminal transition that only the recorded owner may make.

Each of those moves the system from *documented intent* to *enforced invariant*, and each is enforced at the layer where a lie would actually enter — the database, the generator, the transaction — not in a reviewer's memory. That is the structural change: the checks moved inward, into places that cannot be satisfied by writing a convincing paragraph.

The second thing worth naming is what did not move. The release gate stayed `HOLD`. The stock supported path still fails Gate B. The qualification registry still projects the September run and reports `HOLD` for both tracked surfaces. The live Preview database is still four schema-carrying revisions behind the repository head. The independent revalidation returned `INSUFFICIENT_EVIDENCE` and left finding #3 open. The day was productive precisely because none of those had to be dressed up.

## Narrative Log

There was a particular flavour to this day: the day the system got harder to fool. Not harder to use — harder to fool, which is a different thing and, for a system that intends to be depended on, more important.

It arrived in the form of a migrator. The defect itself is old and still open: the stock supported Compose path cannot reach the source tree's migrations, because a bind mount does not carry a symlink target across its boundary, so a stock-launched stack serves the application against a schema behind it. You can see that defect from a mile away — the Preview database has been sitting four revisions behind the repository head, and every qualification in between has been qualified against something other than the stock path. What changed today was the ability to *judge* the outcome. Before, a container exited zero and the operator moved on. Now the launcher identifies the migrator unambiguously, requires it to have reached an exited terminal state with code zero, and then goes and asks the project's own database what `alembic_version` says, requiring exactly one row equal to the expected head. That is a small sentence with a large consequence: the exit code stopped being the evidence and became a precondition for the evidence.

The same instinct showed up in the knowledge graph. The committed DLG projections are derived artifacts — the contract calls them reconstructable and disposable — but for months they were only pinned in a way that trusted everyone. Today a script reads the revision and timestamp recorded inside the artifact itself and asks the generator whether regenerating at exactly those values reproduces the committed bytes. Drift, in that frame, has two names: someone hand-edited the projection, or the corpus moved underneath it and the projection stopped describing it. Both are worth failing a build for. The check was added to CI in the same breath, and it mutates nothing — it validates and reports, which is the correct posture for something that sits between a claim and the truth.

And in the coding worker, the claim moved into the database. A run is no longer started because a worker decided it was starting. Acceptance requires a live PostgreSQL session, an existing matching deployment and canonical run, canonical account and thread lineage, and agreement among every persisted identity assertion; contradictory or malformed lineage is refused outright. The decision is a conditional update that requires `queued` with null ownership, so exactly one worker can win, and the heartbeat and the terminal transition are likewise conditional — only the recorded owner may finish the run, and an escalated run refuses a late completion. The proof receipt that landed with it says the disposition in the plainest possible words: GO for independent reconciliation of this persistence slice, Release: HOLD. It is a claim about a database, and it is scoped exactly to a database.

The parallel track was busier still, and it stayed on its branch. Producers write per-message provenance into `extra_meta`; the reader never selects that column. The decision is made per thread, every returned message is labelled as native regardless, and the exclusion counters count threads where the contract requires per-message counts.
