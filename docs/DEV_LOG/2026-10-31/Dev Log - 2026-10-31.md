## Important outcome

The release-truth pipeline stopped describing a tree it was not on. Before this day, the audit that maintains `00-current-state.md` ran inside a checkout with other executors in it, switched that checkout's branch mid-flight, and committed to a local branch that never reached the remote. So the document a reader consulted was, by construction, at least one cycle behind the code it described. Now the audit runs in a checkout it owns, detached at the fetched tip, and publishes through a guarded path whose commit parent must be that same tip. The audited revision and the published revision are the same git object.

The CI change and the migration test belong to the same discipline. A manual dispatch that skips the backend job and reports success is a green signal meaning "nothing ran." A head-clean migration graph protected by one migration and a recollection is an invariant that decays the moment someone adds a second mergepoint over the same parents. Both were replaced with something that holds on its own.

## Narrative Log

# Dev Log - 2026-10-31

The day was about a quiet question: when a system reports on itself, how much of the report can be trusted? Codexify answers that question in a document, `00-current-state.md`, meant to be the canonical statement of what is true right now. For weeks it was maintained by an audit running inside the checkout everyone else was using, on a schedule that put three writers into one working tree at 05:00, committing to a branch that was never pushed. The failure was not dramatic. It was arithmetic. The document a reader consulted was at least one cycle behind the code it described, and on the day it was finally written down, the tree the audit had audited was twenty commits behind the remote.

What replaced it is deliberately unglamorous. A dedicated checkout that nothing else touches, detached at the fetched tip, so that the revision we audited and the revision we publish onto are the same object. One guarded publisher, shared with the other automated writer to `origin/main`, so the guarantees — parent must be the tip, the tree must change only what was asked, no force, no silent fallback — are enforced in one place instead of assumed in several. And a set of refusal conditions: if the truth document loses its section contract, if its date would move backwards, if `main` shifted while the audit was running, publish nothing rather than publish something degraded.

Two smaller changes belong to the same instinct. A manual CI dispatch can no longer short-circuit into a no-op and report success, because a green check that ran nothing is worse than a red one; it consumes trust it has not earned. And the migration graph's single-head invariant, restored by hand a few days earlier, now has regression coverage that does not assume the current head stays the head. It requires the mergepoint to remain reachable with both of its former heads intact. The invariant outlives the merge that created it.

The day's honest accounting is that this changes how release truth is maintained, not what the release is. The gate is still `HOLD`. The active blockers are the ones from yesterday: a fresh current-tip Compose qualification, the frozen-lockfile install step, cross-browser coverage, the unresolved model-rejection and delegated-adapter contracts. The live Preview database sits where it sat, and a clean graph says nothing about what has been applied to it.

What changed is the trustworthiness of the instrument that measures those blockers. The remaining distance between what the audit says and what is true had been hiding inside the pipeline itself, and it is now closed by construction rather than by care. That is the kind of progress that never appears on a feature list, and it is the kind that decides whether everything else on the list can be believed.
