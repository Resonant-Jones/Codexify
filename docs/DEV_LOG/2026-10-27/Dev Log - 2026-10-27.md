## What I completed

### Saved Widget storage foundation

- Added canonical account-owned widget identity and immutable, numbered revision snapshots, with a migration and database-level integrity constraints.
- Stored provenance as revision history rather than a live dependency on the source thread, so the snapshot can retain its lineage independently.
- The branch documentation describes disposable-PostgreSQL proof. This is storage only: no promotion action, listing, invocation, editing, deletion, export, or Library surface was added.

### Account-authorized agent run readback

- Restored run and thread-run reads using the authenticated account principal as the identity authority.
- Missing authenticated identity fails closed; caller-supplied identity must match the authenticated principal where supplied.
- Added regression coverage distinguishing an unknown run from a run the caller is not authorized to read.

### Direct-message read cursor concurrency

- Serialized each participant's read-cursor compare-and-write against a stable participant-authority row, then refreshed cursor state after acquiring the lock.
- This addresses stale writes moving a cursor backward and concurrent first-read inserts colliding. The change preserves the caller-provided watermark as the upper bound.
- Added a deterministic two-session PostgreSQL regression test for the concurrent interleavings.

### Worker credential-authority assertions

- Updated supported-profile execution tests to bind assertions to credential authority and the execution identity, rather than treating profile support alone as sufficient evidence.

## Important outcome

The common shift was from implicit identity or timing assumptions toward explicit authority and serialized state transitions. Run reads are tied to the authenticated account, message-read progress has a stable serialization point, and Saved Widget revisions have a durable identity and provenance model.

These changes remain branch work. They do not establish that the code is integrated on `main`, that all targeted tests ran today, or that any user-facing Saved Widget capability is available.

## Narrative Log

# Dev Log - 2026-10-27

This was a hardening day, mostly concerned with making authority and ordering explicit. The work landed across several feature branches rather than `origin/main`, so the useful record is both what changed and where it currently lives.

The agent-run readback work corrected an identity boundary: account-scoped reads now derive their principal from the authenticated request context instead of relying on a caller-provided value. The accompanying tests sharpen the distinction between a run that does not exist and one the caller cannot access. That distinction matters operationally because a read path should not silently become unscoped when identity is absent.

The direct-message cursor change addressed a different kind of ambiguity: concurrent writes. Two acknowledgements for the same participant could previously compare against the same old cursor and let a stale watermark win, or collide while creating the first cursor. The implementation serializes that update against a row that exists before the cursor and refreshes state after locking. A deterministic PostgreSQL regression was added for both interleavings; no separate execution receipt for today was available, so the evidence recorded here is the code and test change, not a claim of a newly observed runtime result.

Saved Widgets gained a canonical storage foundation: account-owned identity, immutable revision snapshots, provenance recorded with the revision, and database constraints around the current-revision pointer. The correction worth preserving is the boundary around that work. Persistence exists on the feature branch, but there is still no product action to promote, list, invoke, edit, delete, or export a widget. The storage model is groundwork, not a shipped capability.

The worker-test changes also tightened what counts as valid execution evidence by tying supported-profile assertions to credential authority. Together, these efforts reduce hidden assumptions about identity, concurrency, and persistence. They make later integration easier to judge, but the immediate next step is still ordinary review and merge, followed by targeted proof on the integrated code paths.
