# Dev Log - 2026-08-14

## Summary

This was a recovery-contract and derived-state governance day. The mainline Campaign Engine runtime was rebuilt and polished around provider-free semantics, while ADR-067 defined an operator-approved path for retiring derived Chroma state. The work reduced ambiguity around what can be reconstructed, what can be retired, and what still requires an operator or a live supported-path proof. It strengthened the architecture without turning recovery or data retirement into automatic authority.

- Defined the conditions under which derived state can be classified, preserved, rebuilt, or retired without treating the index as canonical truth.

### Reconstructible context architecture

- Documented reconstructible context and portable reasoning-environment boundaries.
- Clarified which context is durable, which is derived, and which must be re-established rather than silently inferred after recovery.

## Important outcome

Recovery stopped being a vague promise. The system now has a provider-free runtime shape, a named policy for derived Chroma retirement, and a clearer model for reconstructing context after interruption or migration.

The important limit is equally clear: these are architecture and implementation surfaces, not a claim that every supported runtime has completed a live recovery cycle. The operator still decides when derived state may be retired, and the supported profile still needs its own proof.

# Narrative Log - 2026-08-14

This was a day about making recovery a designed behavior instead of a hopeful adjective. The Campaign Engine runtime was rebuilt around provider-free semantics, which gave it a clearer internal shape without pretending that provider independence means provider completion.

The Chroma work addressed the other half of the problem. A derived index is useful, but it is not the canonical record. ADR-067 now gives the operator a defined way to classify and retire that derived state while preserving the possibility of reconstruction. The key change is not permission to delete; it is the removal of ambiguity about who owns that decision and what evidence must exist first.

The reconstructible-context architecture connected those ideas. Context, receipts, and reasoning state cannot all be treated as the same kind of durable object. Some state is canonical, some is derived, and some must be re-established after interruption. Writing that distinction down makes future recovery work testable instead of mystical.

The day therefore produced more boundaries than features, but those boundaries are the useful part. The system can now describe a recovery path, an operator-controlled derived-state path, and a portable context path without collapsing them into one unsupported claim.

The next step is to exercise those contracts under a bounded runtime condition and verify which parts survive an actual interruption, migration, or rebuild.
