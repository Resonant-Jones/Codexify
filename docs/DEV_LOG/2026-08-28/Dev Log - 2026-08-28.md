## Dev Log - 2026-08-28

This was an evidence-correction day more than a feature day. The first correction was in the image-retention record. The repository could still observe the current mutable tag and the present absence of an older image ID, but the predecessor receipts that supported the stronger historical story were not reachable. The right fix was to narrow the claim, not to preserve a convenient narrative. The proof now says what is observed, what is only reported by unavailable predecessors, and what still needs a controlled reproduction.

The second workstream moved to the Chrome extension boundary. The new page-capture broker gives the side panel two explicit read-only modes, selected text and visible page text, and routes them through the service worker rather than letting the UI reach directly into an uncontrolled path. The reader runs in an isolated top frame, excludes sensitive or non-visible structures, bounds content by UTF-8 bytes, and returns versioned sanitization evidence. The trusted side rechecks the result, requires a document identity, rejects unsupported targets, and turns browser exceptions into bounded messages.

The deeper change is that capability is no longer being treated as proof or authority. The image record does not confuse current state with historical causality. The browser seam does not confuse page access with Guardian credentials, persistence, provider calls, or Command Bus authority. Both changes are small in surface area, but they make later runtime qualification more meaningful because the boundaries are explicit before the live proof begins.

There is still no claim of end-to-end browser qualification or fresh supported-Compose closure from this work. The next step is to test the new seam against a real permitted tab and to produce the missing controlled retention evidence, while keeping the release posture conservative.
