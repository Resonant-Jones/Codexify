# Dev Log - 2026-11-07

## Summary

A qualification-truth day, and one of the more honest ones. The work was not "the product got faster" — it was building the machinery that decides whether the product qualifies, correcting a rubric that had three wrong judgments baked into it, and then binding the release-truth document to the repository so it cannot quietly rot again.

Running underneath that was a harder theme: the release truth itself had been eroding. The weekly current-state refresh dropped obligations. Path counts tied to a moving tip leaked into prose. A capability audit and a KB index asserted things the tree could no longer prove. Today's work added validators and tests that bind those claims to the repository, so the next refresh has to clear the same bar. The character of the day is drift prevention, not feature delivery.

## Important outcome

The release truth stopped being a document someone maintains by hand and became a set of claims the repository has to keep. Every version of this truth that has drifted has drifted the same way: a refresh that silently removed something, a count tied to a tip, a README section describing a repository that no longer existed. Today's validators exist because prose alone has now failed to hold that line repeatedly enough to justify trusting prose.

The second structural shift is smaller and just as real. The eight-gate qualification stopped being a document and became a harness — and in the process the rubric had to admit three ways it had been wrong. A rubric corrected in writing before the run is more trustworthy than one never corrected at all, and the report's willingness to say "no gate reached PASS" is the most honest sentence the release lane has produced in a while.

What this does not do is qualify anything. The release gate remains `HOLD`.

## Narrative Log

It was a qualification-truth day, and the through-line was making the system harder to fool with its own paperwork.

The centerpiece was the eight-gate release qualification finally becoming executable. The harness is large — nearly two thousand three hundred lines of evidence collection, a runtime layer, and a self-check — and that size is the point: the release gate had been a description of what ought to be true, which is the weakest possible form of a gate. But the more interesting artifact of the day was the rubric revision. Version 3 exists because version 2 was wrong in three specific ways. The queue/worker gate checked four queues and missed the one a chat completion actually lands on. The deadline gate implied a budget you could configure when the budgets are hardcoded constants. The graceful-stop gate demanded a state that no code path could produce. Each of those would have produced a confident, meaningless PASS. Admitting them, in writing, before running anything, is the opposite of what most release processes do.

The same honesty showed up in the report itself: "No gate reached PASS in this session, because no disposable stack was up." One line, and the entire qualification story for that run is settled. UNPROVEN was reported as UNPROVEN, gate by gate, with the reason attached.

Then the day turned to the release truth, and here it got less comfortable. The weekly current-state refresh had quietly dropped two obligations. Three commits were needed to restore them. That is not a typo — that is a recurring failure mode in a document that is regenerated automatically, and it had already produced a contract test earlier in the week. So the response was not another careful edit. It was binding: the README's Repo Structure section now has a validator, and then that validator's parser bypass was closed, because a validator that can be bypassed was not doing its job. The capability audit got 337 lines of tests. The KB index got 233. Claims that used to live in prose now have to survive contact with the tree.

Elsewhere, quieter and more concrete: the host took ownership of music job attribution, with a mutation proof so the repair is demonstrated rather than asserted; the canonical local node stopped being inferred from age; Scout's document previews became bounded; and the CI workflow stopped cancelling the very suite it existed to run. Each of those is a small repair of a specific lie the system was telling itself.

The underlying shift is worth stating plainly. A release process that produces documents is one thing; one that produces claims the repository has to keep is another. Today moved the work from the first toward the second, and in the process admitted that the rubric — not just the code — had been wrong.

None of it qualifies the product. The gate is still HOLD, both PASS surfaces are stale, and one of them needs two human testers who are not me. But the work today made the difference between "we believe it qualifies" and "here is the evidence, and here is exactly what it does not yet cover" a smaller one. That gap is where the actual release risk lives, and it is finally being narrowed by machinery rather than by attention.
