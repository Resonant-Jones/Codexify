# Dev Log - 2026-11-02

The interesting thing about today is that something failed, and the failure was worth more than the successes.

For months the release gate has been stuck in a peculiar state. It was `HOLD`, obviously, but the reason for the `HOLD` was not a defect. The reason was that the only supported-Compose run on record had tested a commit that was not an ancestor of the current tip, so no one could say whether the supported runtime matched the code being shipped. That is an epistemic failure, and epistemic failures are expensive in a particular way: they cannot be closed by effort, because there is nothing to work on. The work is blocked, but blocked on what?

Today the gate ran. Not a rehearsal, not a smoke test — the real supported Compose runtime, frozen at a revision that genuinely sits inside the tip's lineage, in an isolated project, with the live Private Preview deliberately left alone. And it came back with eight gates, seven of which passed or partially passed, and one that failed. Gate B. The migrator was applying the baked image's Alembic head instead of the frozen source head, so a stock-launched stack would serve an application whose source is two real migrations ahead of the schema underneath it. The receipt does not leave that as a symptom: a diagnostic comparison run applies the same frozen revisions cleanly once the migrator can see the source tree, which pins the cause to the bind mount and clears the migrations themselves. And the repair — source-matched, isolated migrator startup, with an environment-contract test that locks it — was written the same day and pushed to a branch.

Read that again. The gate was `HOLD` before today because nobody could say what was wrong. It is `HOLD` after today because something specific is wrong and someone has already fixed it. Those are very different kinds of `HOLD`, and only one of them compounds. The receipt says `HOLD` in its first paragraph, which is correct and is also the mark of a document that is trying to be useful rather than reassuring.

What stayed still is worth noticing too. The generated qualification registry still reports `supported-compose` as `HOLD` citing a commit that is not in the tip's lineage, and that is not an oversight — the registry's generator discovers receipts from one directory, and today's receipt landed in another. The index is telling the truth about the run it can see; it just cannot see the better run. The release-truth document has the same lag from a different cause: it was refreshed at 15:33, and the qualification merge landed at 16:14. So the evidence advanced and the published index did not follow it. It is a small thing, and it is exactly the kind of drift this repository has spent months building machinery to catch. It is also a reminder that machinery only catches the drift you pointed it at.

The rest of the day had a shape I did not expect, and I think it is worth naming because it will keep appearing. Four unrelated surfaces were hardened against the same failure: auxiliary machinery breaks, the primary thing survives. Inference metering became observe-only, and the specific fix was to wrap the recording of observed provider usage in a guard that catches and logs and swallows — because an instrument that can destroy the thing it measures is not an instrument. The Gallery compatibility alias had a safety rule, and then that rule was withdrawn, because classifying an entry as safe when its source merely *looked* like a server address was insufficiently justified; a syntactically valid server address does not prove the authorized Library projection contains that resource for this account and scope. The replacement fails closed on unverified server references, and the withdrawn observations were preserved in the receipt rather than quietly deleted, which is the difference between a correction and a cover-up. The derived knowledge-graph artifacts are now compared byte-wise against a regenerated candidate before publication, with fallback writes guarded, because a failed regeneration that silently overwrites a good artifact is worse than a failed regeneration. And the migrator fix, discussed already, is the same discipline pointed at startup.

I keep coming back to the withdrawn gallery classification, because it is the one place today where someone found their own work was wrong and said so in public. The first version of that rule looked reasonable. It looked reasonable because "is this a server address?" is a question that is easy to answer, easy to test, and wrong. The browser-local cache is scoped to a browser profile rather than to an account, so the only sound answer to "is it safe to hide this from the user" was never "does it look like a server address" but "can we prove the server projection contains it for this account and scope" — and the answer is frequently no. The gate was rewritten to fail closed because the first gate was a guess wearing the costume of a check.

Three other threads closed on the same day. Message origin, which yesterday's ADR-016 clarification described but did not implement, is now stamped at the creation boundary, atomically with the message insert, and protected from later mutation — origin, ownership, authorship, and placement are different facts, and origin finally has an authoritative source instead of an inference. OpenConnector, which yesterday was still a plan, grew a fail-closed adapter core and a bounded delegated-custody contract behind it, and an upstream advisory was filed and remains under upstream's publication control, which is the correct posture for a coordinated disclosure. And authorized coding intake reached delegation dispatch, guarded by a contract test larger than the feature it constrains.

Two smaller things also belong in the record. The Persona Compiler proposal was written and merged as a document, and it is careful in the way this repository has become good at being careful: a character card is a seed and not a total identity, imported context is context and not biography, and no assistant's identity or memory of its own life transfers when its words do. And the measurement the whole day rests on — that the supported runtime, frozen at one revision, behaves one way rather than another — was recorded as a document that states its own limits before it states its results.

The honest accounting is that the release did not move. The gate is `HOLD` in the published truth. The Preview database is still two persistence-only revisions behind the repository head. The migrator fix is on a branch, the message-origin custody work and the OpenConnector adapter core are unreviewed on branches, the registry has not been regenerated, and the release-truth document describes the world as it was at 15:33. `onboarding-and-people` still has no receipt at all. Nothing here is a release approval, and the receipt that is the day's centerpiece says `HOLD` before it says anything else.

But something specific changed. The system can now say what is wrong with its own supported runtime, and can say it in a document that a machine can check, produced by a run that used a revision the tip actually contains. That is the first time the supported-Compose evidence has been in the same lineage as the code it describes. The next qualification can be a re-run of a known-failing gate against a known fix, rather than another investigation into whether the gate can be trusted at all. Everything else today — the metering guard, the withdrawn gallery rule, the byte comparison, the custody contracts — is the same idea applied more locally: put the thing that measures, checks, or reports where it cannot quietly damage the thing it is about, and where its own failures stay visible. The gate did not open. It stopped being a fog.
