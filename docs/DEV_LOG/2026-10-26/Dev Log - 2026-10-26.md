## What I completed

### Saved Widget architecture contract

- Accepted ADR-102 and its companion contract for saved-widget classification, canonical identity and ownership, server-owned provenance, immutable revisions, invocation, human save authority, and containment.
- The decision is architecture-only. Persistence, listing, save/invoke/revise/delete paths, browser qualification, and release support remain unimplemented or unproven.

### Claim-scoped coding-run heartbeats

- Added a nullable heartbeat timestamp to the canonical `agent_runs` row, constrained to exist only with owner and claim identity. Initial acceptance writes it atomically; renewal is a single conditional update requiring the same run, worker, and claim.
- The worker renews from its own bounded reporter thread and stops that reporter on terminal paths and shutdown. The recorded proof reports a PASS for this slice using disposable PostgreSQL and a separate worker process.
- The heartbeat is activity evidence, not a death verdict. There is no expiry rule, takeover, automatic retry, claim-fenced terminal write, or restart reconciliation.

### Personal Fact candidate review

- Changed archived-status reads so inactive archived facts can be listed when `status=archived`, while the normal active-only behavior remains for other statuses. The page and total use the same effective filter.
- Added PostgreSQL-backed route cases for archived visibility, count behavior, account isolation, and preserving inactive status on read.

### Mobile audit and backend test harness

- Recorded that mobile campaign PR #891 had already merged into `origin/main` on 2026-10-23, correcting the audit packet's stale premise. The audit itself ran no tests or integration; real-device and fresh supported-runtime qualification remain absent, and release posture remains HOLD.
- Stabilized pytest module identity across checkout paths, reconciled test package markers, aligned release-boundary assertions with current state, and added the existing memory-MCP extra to the backend CI install.

## Important outcome

The clearest structural change is the heartbeat boundary: the system can persist and renew activity evidence under the worker claim without silently turning stale activity into permission to reassign, retry, or recover a run. The proof keeps those later decisions outside this slice.

Other changes reinforce the same separation. Archived review does not promote or reactivate data, and accepting the Saved Widget architecture does not create a Saved Widget capability. These are more precise contracts, not a release promotion.

# Dev Log - 2026-10-26

Today was a contract and evidence day spread across several refs. The work touched saved-widget architecture, delegated-worker liveness, Personal Fact review, and backend test collection. The common thread was keeping one kind of evidence from quietly becoming another kind of authority.

The coding worker now has a durable claim-scoped heartbeat. Acceptance records the initial timestamp with the owner and claim, and renewal is conditional on those same identities. A worker can report activity while a synchronous adapter is occupied, and its reporter is stopped during shutdown. The proof receipt records a PASS for this bounded slice, including disposable-PostgreSQL checks and a separate-process disappearance observation. It is careful about the limit: no stale-heartbeat expiry rule, takeover, retry, or restart reconciliation follows from the timestamp. A heartbeat is evidence, not a recovery verdict.

The candidate-review path received a narrower correction. Archived facts are normally inactive, so an archived query must not also require active status. The route now uses the same effective filter for both its page and count, and the new tests exercise that distinction without making a read reactivate the record. This change is also still on a feature ref.

On the architecture side, ADR-102 sets an explicit trust and identity model for future Saved Widgets: ownership, provenance, immutable revisions, and a human-controlled promotion boundary. The contract also says what acceptance does not do. There is no storage or execution implementation, and no new release claim. The mobile audit corrected another kind of drift: its premise that PR #891 had not integrated was stale. It verified the earlier merge while leaving real-device and fresh runtime qualification open.

The test-infrastructure changes address checkout-dependent Python module names and ensure the backend CI install includes an already-existing MCP extra. The heartbeat proof is positive for its bounded slice, but the monolithic backend run remains red and documents both inherited/environment-sensitive failures and one read-only recovery gate that still fails. Those results do not disappear because the slice-specific contract passed.

At the fetched `origin/main` tip, none of today's nine commits is integrated; one is on local `main`, and the rest are on separate refs. The daily log can account for that work, but it cannot make it mainline behavior. The next useful move is review and integration, followed by focused proof on the integrated revision. Recovery semantics and Saved Widget implementation remain separate decisions rather than implied follow-ons.
