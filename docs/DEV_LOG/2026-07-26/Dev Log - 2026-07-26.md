# Narrative Log - 2026-07-26

This was a runtime visibility and UI legibility day. The Settings work was small but deliberate: Appearance is now treated as a canvas, the outer shell keeps its structural job without adding another frame, and card treatment remains where it communicates an actual surface boundary.

The larger correction came from scoped Tailscale loading. The browser was using an LLM health endpoint as its startup gate. A slow provider and model inventory response made the whole shell appear blocked even when the application had rendered. The fix made `/health` the lightweight readiness check, kept retries in the background, and moved degraded status into a bottom notice that does not cover the interface.

The WebSocket failures were separate but related. One proxy rewrote the browser-visible `/api/ws` path away from the backend's canonical route, while the collaboration client could construct an invalid `ws:///...` URL under same-origin routing. Explicit WebSocket proxies and the shared URL resolver remove those sources of ambiguity.

The timing middleware adds bounded operational memory to the path. When enabled, it records method, path, status, duration, request ID, and whether the request arrived locally or through Tailscale. It is not full tracing, but it gives operators enough signal to separate browser, proxy, and backend delay.

The deeper change is that the shell and runtime now have more honest failure behavior. A slow provider probe does not take the UI hostage, a WebSocket path either matches the backend contract or is rejected by the active profile, and timing evidence remains bounded. The next step is to rerun the frontend and backend tests in a repaired environment and keep scoped live proof current.
