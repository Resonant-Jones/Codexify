The two merges are the import recovery stack (#1088, `145e8cbf1`) and multimodal image input on the chat path (#1092, `19e6a3b9e`). They look like two unrelated features. They are the same correction applied twice. The image path used to read a `/media/` file straight off disk with no signature verification and no containment check, and used to fetch media from the worker's own address when the worker had no media mount. The import path used to resume a browser transfer against a loosely-bound selection and used to read manifests without bounding them. In both cases the thing that held the bytes was also the thing that got to decide whether the bytes were allowed to be there. Both days' work moves that decision somewhere it can actually be checked: the signature is verified, the path is required to stay beneath the root, the `documents/` subtree keeps its separate account gate, the selection is bound by a domain-separated digest of every normalized path, size and original content, and a manifest read is bounded before it is trusted.

The other half of the day never touched `main` at all, and it is the larger half. The Scout Android campaign built a native Compose client from an empty directory into a device-verified app in a single day — twenty-seven commits covering credential custody, bounded HTTPS reads, endpoint identity and auth policy, connection settings, conversation and thread reads, canonical turn writes, a message composer, reply reconciliation from Guardian receipts, task-event observation, Guardian Feed and Spaces, the Library, the Inspector, server diagnostics, Markdown transcripts, guarded Mermaid previews and native generative tables — plus two dated receipts on a branch: a bootstrap build qualification and an API 35 emulator smoke proof. And it did it against a **frozen parity baseline**: a table that enumerates what the iOS client does, names the source file for each behaviour, and states Android's status as Implemented, Partial, Missing or Unproven, capability by capability. That document turns "we don't have that yet" from an opinion into a countable list.

### Mainline: multimodal user content on the chat path (PR #1092, `19e6a3b9e`)

Five files, 613 insertions, 59 deletions: `guardian/core/chat_completion_service.py` +221, `guardian/core/ai_router.py` +47, `docs/architecture/chat-runtime-contract.md` +38, and 366 lines of new test across `tests/core/test_ai_router.py` and `tests/core/test_chat_completion_service_image_routing.py`.

This is the day's sharpest correction, and it is a security correction that happens to also be a feature.

- **The old local read was unguarded.** `_encode_image_url_to_base64` joined a URL path onto `GUARDIAN_MEDIA_ROOT` and opened it. There was no media-signature verification, no check that the resolved path stayed beneath the root, and no exclusion of the `documents/` subtree — which the serving route gates with an additional account check. A local read that skips the signature and the containment check is not the same read as the route, and the new contract says so: *"Direct reads require the same media signature as the serving route, stay beneath that root, and exclude document paths, which retain their additional account gate."*
- **The old worker fetch was aimed at the wrong host.** A worker has no media mount, and the fallback asked `localhost:8000` — the worker's own address — for the file. The fix reuses the worker's configured internal Guardian address (`GUARDIAN_INTERNAL_URL`, then `GUARDIAN_COMMAND_BUS_LOOPBACK_BASE`) and retains the signed URL's query string.
- **The image now actually reaches the model.** User attachments become `content` arrays of `text` and `image_url` parts with options preserved, including `detail`; the Anthropic adapter translates data URLs into `image` blocks with a `base64` source, `media_type` and `data`; Ollama keeps its native `images` adaptation. Media stays bound to its authored user message, and in bounded history a prior image stays available for a follow-up question without being reassigned to the latest turn.
- **It fails loudly instead of silently.** An unavailable private image or a missing source raises `CHAT_COMPLETE_IMAGE_PAYLOAD_MISSING` *before* dispatch, rather than losing the image or forwarding a private media signature. Public image URLs remain valid provider inputs when local conversion is unavailable.

The contract states its own limits without being asked: this is request adaptation under existing thread and provider authority, aligned with ADR-003, ADR-069 and ADR-091, and it adds no persistence schema, no provider or model selection rule, no audio or video input support and no release claim.

## Important outcome

`main` changed shape today, and the more interesting half of that change is what it revealed about the release-truth surface.

For two days the honest description of `main` was that it accepted documents only, and the weekly current-state document said exactly that in its own words: *"The only commit to land on `main` since the last audit is a dated dev log... No code, route, migration, contract or qualification surface changed."* That sentence was written at `3a6dc0b0f` (10:11 UTC) and it was true there. Then #1088 landed at 22:06 UTC with a 27-file import stack, a new service module, new routes, a new protocol token and a changed qualification surface, and #1092 landed at 23:39 UTC with 613 lines across the chat completion service and the AI router. **Read at the tip, the published current-state document is stale by exactly two merges — and it is dated 2026-11-18, so nothing on its face signals that.**

That is not a criticism of the document; it is the document's own warning, applied to itself. It already says *"A green run does not survive the merge that publishes it."* What happened today is that a *document* did not survive two merges that followed it. The priority list is stale in the same way: priority 12 still asks for the import workstream to be landed from one reconciled base, and the day landed it — #1088 into `main`, #1089 into it first, in the order the document demanded.

The counterweight is that the machine-checkable half of the truth held. I ran the qualification registry gate against the tip in an isolated worktree: `scripts/qualification/generate_registry.py --check` reports **OK** — `docs/qualification/registry.json` matches the projection at tip `19e6a3b9e`. The `Qualification Contracts` workflow also ran green at the #1088 merge at 22:06:51 UTC. The changed-path counts moved, from 62 and 169 in the published document to **63 and 181** at the tip, and both `PASS` surfaces are still `stale` and both `HOLD` surfaces still have no receipt — but the projection and the committed registry agree, which is the thing that is actually gated. `Guardian CI` is green at the tip as well: all five jobs succeeded on run `44422634800`.

So the day's shape is this: prose truth went stale, machine-checked truth did not. That is a better outcome than the reverse, and it is also the reason the prose truth needs the same discipline the registry gets. The gap is not that the document is wrong — it is that it has no gate, and the merge that invalidated it was the merge that carried real code.

The second structural shift is quieter and may outlast the first. The Scout Android campaign did something I have not seen in this repository before: it froze a **cross-platform parity baseline** before writing the code. Eleven capability areas, each with the iOS behaviour, the iOS source file that implements it, and Android's status stated in one of four words. That table is what turns "the Android client is behind" from an assertion into a countable claim — and it is countable in a way that can be re-derived rather than remembered. Today it reads Mostly Missing and Partial at the freeze, and the day's twenty-seven commits moved it substantially. That is a much better instrument than a status page, because it is falsifiable.

## Closing thought

Eighty-one commits, and for the first time in three days the interesting question is not whether `main` accepted anything. It accepted two stacks, both of which made a system less willing to act on its own belief and more willing to act on a check.

The media path used to open whatever it was told to open. Now it verifies the signature, requires the path to stay under the root, keeps the `documents/` account gate intact, and fails with `CHAT_COMPLETE_IMAGE_PAYLOAD_MISSING` rather than quietly dropping an image. The import path used to resume against a loose idea of "the same selection". Now the selection is a domain-separated digest over every normalized path, every size and every original byte, compared before a single file is transmitted, and the server's own owner-scoped manifest is verified independently. Neither change is dramatic. Both are the difference between a system that trusts possession and a system that trusts proof, and the day was about moving several places from the first to the second.

What I want to hold onto is the smaller, stranger win: the Android parity baseline. Eleven rows, each naming the iOS file that implements a behaviour and stating Android's status in one of four words. It is the first artifact in this repository I have seen that turns a vague sense of being behind into a list you could check off and re-derive. The client it describes was built from nothing on the same day it was written down, which is a strange efficiency — the plan and the implementation came out of the same understanding. I would like more of that: measure the gap before you start closing it, in a form that survives the day.

And I want to remember the drift. The published current-state document said, in its own words, that a green run does not survive the merge that publishes it. It did not anticipate that a *document* would not survive the two merges that followed it — two merges carrying exactly the code and contracts it was there to describe, landing at 22:06 and 23:39 UTC on the day it was written. The registry gate stayed true through both. The prose did not. I do not think that is a failure of discipline; I think it is the first time the gap between the two kinds of truth has been visible in this repository, and the useful thing to do with that is to build the same gate for the prose that exists for the projection.

# Dev Log - 2026-11-18

A day where `main` stopped being a place where documents go to be measured, and started being a place where code goes to be judged. That is the whole headline, and it is worth saying before anything else, because for two prior days the honest description of `main` was that it took nothing but prose about how little it took. The count today: eighty-one commits in the 2026-11-18 UTC window, twenty-seven of them ancestors of the tip of `main`, fifty-four on branches. Two pull requests merged with real code in them. The release gate did not move — `HOLD` at the start of the day, `HOLD` at the end — and no proof artifact dated today exists on `main`. But the thing that changed is not the gate. The thing that changed is that `main` now contains a hundred and fifty lines of import transport and two hundred and twenty lines of chat completion service that were not there yesterday.

Let me take the two merges separately, because they look like a coincidence and are not.

The first is the import recovery stack, and its subject is a question that sounds dull and is not: when a browser resumes an upload, how does it know it is resuming the same upload? The old answer was loose. The new answer is a domain-separated SHA-256 aggregate over every normalized path, every size and every original file content, computed before the job is created, reduced to a single digest plus the source and the server origin, and compared — in full — before any missing file is transmitted. The server's own owner-scoped staged manifest is then verified independently, so the browser's claim is not the authority; the browser's claim is a *claim*, and the server checks it against what it actually holds. Same-size changes and renamed pending paths fail closed. A resume or status 404 archives the exact browser checkpoint under a namespaced key before clearing only its active reference, and if the archival fails, the reference stays. That last detail is the one I keep thinking about, because it is a refusal to be optimistic about a failure: the system would rather keep a stale pointer it can explain than destroy evidence it might need.

And the limits are written down without being asked for. The browser digest is not a server-enforced declaration, not a source-account certificate, not account authority, not an archive parity receipt, not protection against a modified client. Legacy receiving jobs have no historical declaration for unstaged bytes, so no retrospective digest can prove that missing identity — and rather than paper over it, automatic continuation is simply *blocked* while the existing job and its staged bytes remain retained, with the interface refusing to tell the user to delete, abort or discard those jobs. And the closing line of the review document is the honest one: this change is not deployed by merging it. Four of the day's fourteen import commits are not product work at all. One makes the recovery fixtures portable to Node 22, because a test that behaves differently on CI than on a laptop is not evidence. One normalizes a cross-realm SHA-256 fixture, for the same reason. One verifies retained checkpoints against the actual storage fixture rather than a mock. Fixing the tests is unglamorous and it is the reason the rest of the tests mean anything.

The second merge is the one I find sharper, because it is a security fix wearing a feature's clothes. The image path is supposed to take a picture the user attached and get it in front of a model that can see. What it actually did was join a URL path onto a media root and open the file. No signature check. No requirement that the resolved path stay under the root. No exclusion of the `documents/` subtree, which the serving route gates with an extra account check that a direct local read simply walked past. And when there was no local root, a worker — which has no media mount — asked its own `localhost:8000` for the file, which was never going to be the thing serving it.

The merged version verifies the media signature the same way the serving route does, resolves the path and refuses anything that is not relative to the root, keeps `documents/` out of the local-read path entirely so the account gate cannot be bypassed by a shortcut, and when it must fetch over HTTP it goes to the worker's configured internal Guardian address, preserving the signed query. And when the image genuinely cannot be obtained, it raises `CHAT_COMPLETE_IMAGE_PAYLOAD_MISSING` before dispatch — which is the sentence I would put on the wall. Losing the image silently, or forwarding a private media signature to a provider, are both the kind of failure that looks like success. This one refuses to look like success.

Underneath both merges is the same move, and I do not think it is a coincidence that the day produced two instances of it. In each case, the component that *held* the bytes was also the component that got to decide whether the bytes were allowed to be there. The fix is to separate those: the holder fetches, the checker authorizes, and the authorization is re-derived at the moment the side effect happens rather than trusted from an earlier moment. The import side re-derives the selection fingerprint and the owner-scoped manifest before each transmission. The media side re-derives the signature and the containment before each read. Neither trusts possession.
