# Narrative Log - 2026-07-22

This was a runtime visibility and control-boundary day. The work corrected several places where asynchronous behavior could become ambiguous: a browser could keep polling a job that no longer existed, a worker could inherit older result assumptions, and cancellation could stop locally without reaching the active Whoosh'd operation.

The import fix was small but clean. A persisted 404 is not an unfinished transfer; it is a stale reference. The coordinator now clears it, reports a bounded failure, and stops scheduling more requests.

The deeper work was in Guardian. Request identity now has a deliberate shape: one root request, one queue task, one attempt per provider execution, and one local Whoosh'd request. These identifiers are bounded, content-free, and carried through the places where the operation changes form. This is smaller than distributed tracing by design, but gives the system enough structural truth to connect worker events, provider attempts, runtime provenance, and persisted results.

Cancellation became the practical test of that identity. The monitor can find the Whoosh'd request from response metadata or runtime discovery, issue a request-specific cancellation, and return explicit cancelled terminal evidence. The worker can now distinguish cancellation from an incomplete stream that might otherwise be retried or misclassified.

The result is better operational memory at the code and focused-test level. The current release truth remains local-first beta on Compose, and no live Whoosh'd cancellation proof was established today. The next step is to run the frontend test in a complete environment, then exercise correlation and cancellation against the supported runtime.
