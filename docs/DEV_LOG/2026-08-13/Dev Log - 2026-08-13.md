# Narrative Log - 2026-08-13

This was a day spent making the system honest about what happens when the normal path breaks. The work began with migration history and runtime dependency selection, where a driver mismatch and a damaged lineage can look like ordinary startup failures if they are not separated carefully. Mainline now has a canonical psycopg3 path and a repair that preserves the historical record instead of rewriting it into convenience.

From there, the proof work moved outward. Preserved tester startup and authentication were recorded as their own evidence. Chroma startup isolation and store-generation reconciliation were recorded as derived-state concerns rather than confused with canonical persistence. That distinction is operationally important: a derived index can be rebuilt or retired under an explicit policy, while the source of truth must remain protected.

The Campaign Engine work added a recovery contract to the same picture. It describes how bounded provider-free execution should recover and how receipts should remain identifiable, but it does not pretend that a contract has already completed a live run. The Atlas and Room follow-through kept owner/guest semantics and migration readiness in their own lanes.

The deeper change is that the system now has a more legible failure map. Migration lineage, runtime dependencies, preserved tester state, derived Chroma state, and Campaign Engine recovery are no longer one undifferentiated “startup” problem. Each has a named boundary and a narrower proof obligation.

That makes the next proof campaign slower in the useful way. The project can test one gate at a time, know what a failure belongs to, and avoid repairing the wrong layer because several symptoms happened to appear together.
