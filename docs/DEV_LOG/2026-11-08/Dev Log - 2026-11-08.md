## Narrative Log

# Dev Log - 2026-11-08

It was a verification day, and the two halves of it turned out to be the same idea at different altitudes.

The constructive half was CI. The problem it solves is nasty in the specific way only CI problems are nasty: a documentation-only push to the tip of `main` used to produce a green "Backend Tests" check whose pytest step had never run. The job's only executed step was the echo announcing that it was skipping the suite, and the echo's success became the check's success. Anyone reading that check on a release-review screen would conclude the suite had run and passed. The fix was to stop letting the tip decide to skip — a push to `refs/heads/main` now always sets the backend and frontend run flags true, while the superseded-revision check still no-ops so the runner cost stays bounded. Twenty-five lines.

Twenty-five lines would have been the whole story if the day had ended there. What made it worth an entry is what came four hours later: someone noticed that fixing the workflow is a claim *about* the workflow, and a claim about the workflow cannot be proven by the workflow. So the matrix became a test file that extracts the `Compute run matrix` step body out of the YAML, renders the GitHub expressions, and executes it. It does not restate the matrix — a test that restated the matrix would stay green if someone reordered the branches, which is the exact bug it was written to catch. It reads the step's own `if:` condition and evaluates it, with `git ls-remote` shimmed, so what is under test is the real composition. Twelve named scenarios, five dedicated assertions about the superseded branch, seventeen cases, all passing against the tip.

The honest half arrived in the day's last commit, and it is the one worth keeping. The weekly release-truth refresh had to state what had changed recently, and in doing so it had to confront a claim that was no longer true: the eight-gate harness's self-test does not pass at this tip. It reports fifty-three of fifty-four. The single failure is the migration gate's expectation that the evaluated checkout's head is `a7d4c9e2f1b3` — the head when the harness shipped — while the tip's head is `b3f8c2d1e907`. The defect is in the frozen expectation, not the harness; the harness computes the head from the checkout's own source and hard-codes no head. And then the document said the harder thing: the previous audit's claim that the self-test passed fifty-four of fifty-four was already false at its own tip, because the head had advanced before that audit ran.

That sentence is the day, honestly. A release-truth document that admits its own prior claim was wrong is doing a different job from one that lists accomplishments. The first can be trusted when it says something is not working. The second can only be trusted about the things that went well, which is the half that never needed auditing.

There was quieter honesty in the details. The frozen `a7d4c9e2f1b3` is not a one-off glitch; it is a fixture that will turn red on every migration landing until the expectation is derived instead of pinned. And when the head cannot be computed at all — which I hit in a bare interpreter without Alembic — the harness's error path returns a dictionary without the `heads` key that the self-test then indexes unconditionally, so an environment error becomes an unhandled `KeyError` instead of a reported failure. Neither of those caused the fifty-three. Both are the kind of thing you only notice if you run the thing instead of reading about it.

Elsewhere the day was quieter still. The archive caught up in both directions, publishing the 2026-11-07 log and, six months behind it, a reconstruction of 2026-05-03. Two worktrees carried a sidebar-control change — a real one, with `aria-expanded`, a state-tracking label and a geometry spec — that exists on no published ref, so it is not part of the product and not part of the release truth either. Just work in progress, honestly labelled.

None of it moved the gate. The gate is still HOLD, both PASS surfaces are still stale, both HOLD surfaces still have no receipt, and one of them needs two human testers who are not me. What today changed is smaller and more durable: the distance between "the system says it is fine" and "the system checked." That distance was already the substance of the work. Today it closed by one commit in each direction — one that made a check real, and one that let a check fail.
