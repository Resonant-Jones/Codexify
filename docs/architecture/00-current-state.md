## Current supported reality

- The named supported install path is local Docker Compose profile `v1-local-core-web-mcp` with `LLM_PROVIDER=local`, `CODEXIFY_LOCAL_ONLY_MODE=true`, `ALLOW_CLOUD_PROVIDERS=false`. The startup path is part of that supported path, and the two available startups are not interchangeable. The Beta Supported envelope covers local inference, ordinary chat, durable threads/messages/tasks, supported document ingestion and retrieval, account ownership, migrations, and operator diagnostics. Qualification is a separate gate.
- **Stage 1A accepted-chat source custody is implemented in this tree.** Eligible ordinary chat persists the original account and exact canonical user-message ID after revalidating the selected authored turn under lock and before queue publication. The pre-selection resolver checks that stored source without reselecting the newest message. The [local proof](proofs/2026-11-27-accepted-chat-source-custody.md) covers the authored-turn path, ordinary embedding metadata updates and repeatable migration behavior in disposable PostgreSQL. Accepted content revision, durable native-origin custody, shared-worker dispatch, and historical-read authorization remain separate. Ordinary-chat historical reads stay disabled. No serving Preview migration or release qualification was performed for Stage 1A.
- **The Private Preview's PostgreSQL application database has a verified, dated recovery checkpoint** at `ab71d5ce9604`: the archive was dumped and re-hashed, restored into an isolated disposable container, and its census matched the source. It is preview-lane recovery evidence for the database only, not a release qualification and not a full-environment backup. Six source revisions separate that checkpoint from this tree's head.
- **OpenAI import Project routing is merged source with enforced placement rules.** The account owns its logical import sources, a source is explicitly selected before a new upload starts, and the staged job stores its source ID at admission so retries and resumed uploads retain it. The first accepted fresh conversation in a group creates one owned Project and one mapping keyed by (owner, source, exact group ID) in the same transaction as its canonical write. Full-account export uses `account-export.v9` when that state exists, and an older format refuses it rather than dropping it. **Coverage is code, route and disposable-PostgreSQL level only.** No dated proof artifact, no qualification surface, and no live account import.
- **User image attachments now reach a vision-capable model as image content.** The attachment path is merged source with real fixture bytes and mocked transport in the regression tests. `LOCAL_VISION_MODEL` is set nowhere in the supported profile, so the worker's image-to-vision-model override is inert by default and the merge adds no provider or model selection rule. **Coverage is code and mocked-transport level only.** No dated proof artifact, no qualification surface, and no live provider understanding.
- **The account-import transfer path is merged, bounded and owner-scoped.** Chunk upload, manifest readback, verified recovery and idempotent transfer are on `main` with unit, route and disposable-PostgreSQL tests. **The browser-side selection fingerprint is continuity evidence only** -- not a server-enforced declaration, not a source-account certificate, not account authority, not an archive parity receipt and not protection against a modified client. Legacy receiving jobs have no historical declaration for unstaged bytes, so automatic continuation stays blocked for them.
- **Account-scoped history recall is implemented on `main` and mounted.** `GET /api/chat/projects/{project_id}/history/search` resolves the account from authenticated authority only, and it is reachable on the supported profile because route posture is per-router and `api_chat` is in that profile's `enabled` posture. The model-facing `op::history.search` tool is advertised only when a request-scoped grant is present. Coverage is code and test level only. **Reader-side per-message origin classification exists; durable same-row custody is pending.** `guardian/core/message_origin_classification.py` classifies each candidate message at read time from its own persisted evidence. No schema change, no migration, no backfill. **Accepted architecture is distinct:** the `native_origin_custody` column, migration, trusted creation-only writers, PostgreSQL immutability and custody-aware reader verification are unimplemented -- the identifier appears nowhere in `guardian/` at this tip.
- **Saved Widgets expose more than promotion.** Behind `CODEXIFY_ENABLE_SAVED_WIDGET_ROUTES`, and mounted `enabled` on the supported profile, the API carries `POST /saved-widgets`, `GET /saved-widgets`, `GET /saved-widgets/{id}`, `POST /saved-widgets/{id}/revisions`, `GET .../revisions` and `GET .../revisions/{rev}`.
