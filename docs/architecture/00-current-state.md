## Interpretation rule

## Current supported reality

- The named supported install path is local Docker Compose profile `v1-local-core-web-mcp` with `LLM_PROVIDER=local`, `CODEXIFY_LOCAL_ONLY_MODE=true`, `ALLOW_CLOUD_PROVIDERS=false`. The startup path is part of that supported path, and the two available startups are not interchangeable.
- The Beta Supported envelope covers local inference, ordinary chat, durable threads/messages/tasks, supported document ingestion and retrieval, account ownership, migrations, and operator diagnostics. Qualification is a separate gate.
- The repository migration graph is a single head, `d8a90bf32107`. A head-clean graph is a repository invariant, not a deployment qualification. Earlier live Preview migration evidence applies to its serving source and does not qualify this new source revision. No Preview migration was performed for the custody, credential or connector OAuth changes.
- **The Private Preview's PostgreSQL application database has a verified, dated recovery checkpoint** at `ab71d5ce9604`: the archive was dumped and re-hashed, restored into an isolated disposable container, and its census matched the source. It is preview-lane recovery evidence for the database only, not a release qualification and not a full-environment backup. Two migrations have landed on `main` since it.
- **Account-scoped history recall is implemented on `main` and mounted.** `GET /api/chat/projects/{project_id}/history/search` resolves the account from authenticated authority only, and it is reachable on the supported profile because route posture is per-router and `api_chat` is in that profile's `enabled` posture. The model-facing `op::history.search` tool is advertised only when a request-scoped grant is present. Coverage is code and test level only. **Reader-side per-message origin classification exists; durable same-row custody is pending.** `guardian/core/message_origin_classification.py` classifies each candidate message at read time from its own persisted evidence, and the recall reader excludes imported, unknown and conflicting messages before excerpts reach the model. No schema change, no migration, no backfill. **Accepted architecture is distinct:** the `native_origin_custody` column, migration, trusted creation-only writers, PostgreSQL immutability and custody-aware reader verification are unimplemented -- the identifier appears nowhere in `guardian/` at this tip.
- **Saved Widgets now expose more than promotion.** Behind `CODEXIFY_ENABLE_SAVED_WIDGET_ROUTES`, and mounted `enabled` on the supported profile, the API carries `POST /saved-widgets`, `GET /saved-widgets` (account-wide paginated collection listing), `GET /saved-widgets/{id}`, `POST /saved-widgets/{id}/revisions` (explicit new-version append), `GET .../revisions` and `GET .../revisions/{rev}`. Web Library and Scout can list, select and launch an immutable revision client-side. This is still not a qualified widget lifecycle, and the widget UI ships behind the `VITE_GENERATIVE_UI` build flag, which is off by default.
- **The coding-worker lane is merged code, not qualified execution.** Claim persistence is in `guardian/agents/store.py`; the pre-acceptance refusal is deployment-scoped and fenced. None of these merges lifts the gate.
- **The Music Producer surface is merged code behind a quarantining profile.** `music_projects` is not in the default profile's route posture; it is reachable only under `v1-music-producer`, which is not a qualified supported path. ADR-108 is proposed, not accepted. **The host owns the job's attribution**: it records which project a music job belongs to when the handle is minted, in its own `music_jobs` table.
- **The Private Preview lane accepts OpenAI chat** (`56caf2cfd`), with a documented serial rollout (`42a507897`). It is a preview-lane capability with its own rollout order, not part of the Beta supported envelope.
- `direct_messages` is mounted `internal_only` on the supported profile. **Private document shares are bound to recipient accounts**: `direct_message_document_shares` holds one revocable grant per shared document. Share *links* are a different surface and remain bearer credentials: `expires_in_days` is optional on creation and no revocation endpoint exists.
- **Scout is a preview-lane native client, not a supported Beta surface.** Its qualification and handoff routes ride under the `auth` route label, which is absent from the supported profile's posture and therefore quarantined there; they mount on the tester profile. The hosted account transport additionally requires `GUARDIAN_EXPOSURE_MODE=private_preview`.
- **The Feed (customizable scrolling dashboard stack) and the Inspector (Workspace drawer tab that now receives documents opened from Feed, Library or chat) are shipped web-UI surfaces of the supported local Compose path.** Their evidence is code and unit test only: no dated proof artifact and no qualification surface exists for either.
- Recipient-local read state is deployed and live-qualified on the Private Preview: a two-account live test passed 20 of 20 checks, re-run against the merged mainline. The unread badge is browser-rendered and proven in Chrome 156 on one browser only.
- Ordinary chat, durable persistence and readback, retrieval with source attribution, browser-driven event coherence, and restart recovery are proven at frozen revisions. Bounded evidence is not complete runtime qualification; per-message `retrieval_provenance` remains the carrier of retrieval truth, and the operator retrieval surfaces are not trustworthy as evidence on their own.
- Connectors, activation, browser host/import, Watchdog, hosted sandbox, Atlas, Pi, federation, and autonomous coding-worker work are not default Beta support without current-main qualification.
