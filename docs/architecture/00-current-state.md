## Active blockers

- **The stock supported Compose startup has no qualification of its own.** Its migration-source incoherence has a bounded correction in the tree and a stock-path Gate B proof; neither is a qualification. The `supported-compose-stock` rubric, its run and its receipt do not exist, and the stock startup's Gate A–H coverage beyond the migration gates has never been executed.
- `onboarding-and-people` has no qualification run receipt at all, so the registry reports `HOLD` for it on absent evidence rather than on a lineage or staleness cause. A supported-Compose run does not qualify this surface.
- The current-tip supported-Compose qualification is missing, and the registry's `supported-compose` entry is `stale` against this tip because twelve paths in its surface changed after the 2026-11-03 run. A qualification is commit-bound, so no supported-Compose qualification describes the current tip.
- The live Preview database has not been advanced past `3a91d7c4e8b2`; five schema-carrying revisions and two mergepoints on `main` are unapplied there.
- **Reader-side per-message origin classification is not implemented.** Imported, unknown, and conflicting messages are not excluded before excerpts reach the model, and no content-free per-message coverage receipts are produced. The governing contract carries this as an open finding.
- A killed `worker-document-embed` leaves the affected document permanently in `embedding_status = 'processing'` with no observed recovery path.
- The rag-trace and retrieval-posture operator surfaces report empty even when retrieval demonstrably succeeded.
- Three `[trio]`-parametrised retrieval selectors cannot execute, so they are INCOMPLETE rather than passes. `trio` is pinned only in the unreferenced legacy `requirements/backend-old.txt`; it is absent from every active install input (`backend/requirements.txt`, `requirements/base.in`, `requirements/all.txt`), so the supported path never installs it.
- Frontend frozen-lockfile installation on the supported install path remains unrehearsed, and cross-browser qualification is missing on both the generative-UI containment repair and the unread badge; Chrome 156 is the only reported browser result.
- The UMS/Chronicle lane retains an inherited stale migration-head assertion, and blocked Chronicle HTTP coverage still needs execution against the corrected baseline.
- The delegated worker-to-adapter `reasoning_effort` contract still fails before provider execution, and worker egress was observed despite `allow_network=false`. Explicit-model rejection is proven only at the frozen revision — not on the stock path and not at this tip.
- New-thread projection, natural import-to-recall, scope isolation, export/restore/retention, and complete conversation-lifecycle proof remain open. Private Preview still lacks share-link expiry/revocation, cross-node messaging proof, and consent-enforcement coverage at a profile that mounts `iddb`.
- The Saved Widget lifecycle is incomplete beyond promotion and revision storage: no Library Widgets collection listing, invocation, conversational editing, deletion, or export and restore path, and no browser proof.

The schema-only `status` column carries no runtime semantics and nothing transitions it, the read path never filters on it, and no production caller deletes rows — while the SSE path deliberately retains them so concurrent clients can resume independently. 6. Implement the reader-side per-message origin classification and exclusion for the recall reader, and emit content-free per-message coverage receipts, so the open finding can close on evidence rather than intent.
7. Characterise the document-embed failure path under a kill injected at a controlled point, so `processing` documents are either recovered or terminally failed.
8. Populate the rag-trace and retrieval-posture surfaces, or mark them as non-evidence, so operator-facing retrieval diagnostics can be qualified rather than only per-message provenance.
