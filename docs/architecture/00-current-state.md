## Interpretation rule

This file is authoritative for release readiness, the supported install path, active blockers, current priorities, and what is and is not part of the present release promise.

Every runtime or implementation claim below is stated against `origin/main` only. Work that exists on a branch, in a draft, or in an open pull request is recorded as intent, never as shipped reality. Explicitly approved governance decisions may be recorded locally before publication; their acceptance does not imply implementation, merge or release qualification.

## Current supported reality

- The Beta Supported envelope covers local inference, ordinary chat, durable threads/messages/tasks, supported document ingestion and retrieval, account ownership, migrations, and operator diagnostics. Qualification is a separate gate.
- The repository migration graph is a single head, `ab71d5ce9604`. A head-clean graph is a repository invariant, not a deployment qualification. The live Preview database tracks the serving source's head, with the image's baked migration source proven byte-identical to the served checkout by SHA-256 inside the image and the live `alembic_version` read directly out of PostgreSQL as one row.
- **The Private Preview's PostgreSQL application database has a verified, dated recovery checkpoint** at `ab71d5ce9604`: the archive was dumped and re-hashed, restored into an isolated disposable container, and its census matched the source. It is preview-lane recovery evidence for the database only, not a release qualification and not a full-environment backup.
- **Account-scoped history recall is implemented on `main` and mounted.** `GET /api/chat/projects/{project_id}/history/search` resolves the account from authenticated authority only, and it is reachable on the supported profile because route posture is per-router and `api_chat` is in that profile's `enabled` posture. The model-facing `op::history.search` tool is advertised only when a request-scoped grant is present. Coverage is code and test level only. **Native assertion write custody and reader classification exist; durable same-row custody is pending.** `guardian/core/message_origin_classification.py` classifies each candidate message at read time from its own persisted evidence, and the recall reader excludes imported, unknown and conflicting messages before excerpts reach the model. The coverage receipt carries content-free per-message exclusion counts separate from thread-level counters. No schema change, no migration, no backfill. **Accepted architecture is distinct:** the `native_origin_custody` column, migration, trusted creation-only writers, PostgreSQL immutability and custody-aware reader verification are unimplemented -- the identifier appears nowhere in `guardian/` at this tip.
- **The coding-worker lane is merged code, not qualified execution.** Claim persistence is in `guardian/agents/store.py`; the pre-acceptance refusal is deployment-scoped and fenced. None of these merges lifts the gate.
- **The Music Producer surface is merged code behind a quarantining profile.** `music_projects` is not in the default profile's route posture; it is reachable only under `v1-music-producer`, which is not a qualified supported path. ADR-108 is proposed, not accepted. **The host owns the job's attribution**: it records which project a music job belongs to when the handle is minted, in its own `music_jobs` table, so the finished files are placed against the right project even when the service echoes nothing back.
- **The Private Preview lane accepts OpenAI chat** (`56caf2cfd`), with a documented serial rollout (`42a507897`). It is a preview-lane capability with its own rollout order, not part of the Beta supported envelope.
- Saved Widget **promotion and revision storage** exist on `main` behind `CODEXIFY_ENABLE_SAVED_WIDGET_ROUTES`. This is a promotion and revision-storage slice only, not a qualified widget lifecycle.
- `direct_messages` is mounted `internal_only` on the supported profile. **Private document shares are bound to recipient accounts**: `direct_message_document_shares` holds one revocable grant per shared document, and signed document ownership is resolved from the Guardian database. Share *links* are a different surface and remain bearer credentials: `expires_in_days` is optional on creation and no revocation endpoint exists.
