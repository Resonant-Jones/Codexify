## The validator

Create `tests/architecture/test_changelog_currency.py`. It must implement the
rules below, each deriving truth from the repository rather than hardcoding it.

### Rule 1 — no link in a changelog may point at a tag or release that does not exist

This is the rule that catches the defect. `CHANGELOG.md`'s nine version links
all 404 today. A changelog that links to releases that were never made is
fiction dressed as history.

A version link is checked against `git tag --list` and `gh release list`, or —
so the check does not depend on network access — against the repository's own
tag set.

### Rule 2 — the changelog states where release truth actually lives

Whichever changelog is the release artifact, it must name the documents that
actually govern release, and those documents must exist.

### Rule 3 — `CHANGELOG.beta.md`'s sections are in date order

This is a **live defect in a maintained artifact**, independent of D1.

`scripts/release/beta_release_sentinel.py:313` appends each new section to the
end of the file:

```python
lines = [existing, "", f"## {date_str}", "", "### Evidence"]
```

so the newest entry lands **last**. The file's sections are currently
`2026-06-12`, `2026-05-15`, `2026-05-15`, `2026-05-15`, `2026-11-06` — the
newest date is at the bottom, and the oldest is at the top. A reader looking
for the most recent change has to read to the end.

This is the same failure class as the weekly current-state override: a
mechanism that appends without ordering, producing a document that is always
sorted wrong. The fix is to insert the new section in date order, and the
check is that the sections are non-increasing.

### Rule 4 — a new section is inserted, not appended

This is the *prevention* for Rule 3, and it is a behavioural requirement on the
generator rather than a check on the file. A test that only reads the produced
file cannot prevent the next append from being misordered; only the generator's
behaviour can.

## Required test

The validator gains a committed test exercising **both** a valid input and a
malformed input — the improvement the TS-002 reconciliation identified.

For Rule 4 in particular, the test must exercise the **generator function**
with two sections in a known order and assert the resulting file is ordered —
not merely read the file the generator happened to produce last.
