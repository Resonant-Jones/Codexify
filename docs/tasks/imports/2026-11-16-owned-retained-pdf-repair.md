# Repair one retained imported PDF without replacing an import

Lane: architecture-impact, aligned with existing account-owned imports and imported provenance. Priority P1: a supported PDF can be skipped because extracted text contains NULs rejected by PostgreSQL, although its original bytes remain safely staged. The owner explicitly authorized necessary reviewed corrections and safe same-job recovery. No release or Beta support claim changes.

Current authority anchors: `00-current-state.md` (release HOLD), ADR-005 account boundaries, ADR-016 imported/archive distinction, ADR-069 release boundaries, ADR-081 Project ownership, runtime-token contract, existing account-import ownership and zero-write retry implementation. This is a narrow owner-authenticated imported-file repair; it is not generic restore, native upload, model recall or the separate immutable-export-identity proposal.

Constitutional answers:

1. The account-owned terminal job, its accepted fingerprint and immutable staged path/size/SHA manifest are authoritative. Canonical media/document/Project ownership and stored original bytes determine whether repair succeeded.
2. Client file metadata and submitted identity are evidence only. The server rechecks every value and derives provenance only from verified accepted source bytes.
3. Capability: normalize invalid derived PDF text, then repair one previously attempted retained PDF under that same job after ordinary processing has ended.
4. Normal authenticated owner authority and this explicit human recovery task authorize the action; provider IDs, operator keys and caller user IDs do not confer ownership.
5. Original bytes and all original checkpoints/warning/skip history remain untouched. Canonical imported document/link rows and append-only repair audit facts become durable under the same account/job.
6. Completion requires owned canonical rows/lineage, unchanged original SHA/size, exact-once audit/counter accounting, authenticated owner read/download and source coverage evidence. HTTP acceptance alone is insufficient.

Implementation boundary:

- Normalize NULs on both PDF extraction paths to visible replacement characters; NUL-only output is unavailable text. Preserve PDF bytes.
- Add a separate owner-authenticated single-PDF repair POST and read-only audit GET. Generic FAILED + zero-write retry remains unchanged. No job status, schema, queue, worker or accepted fingerprint change.
- Require completed-with-warnings, OpenAI source, matching accepted path/size/SHA/fingerprint and a previously checkpointed media path. Reject active work, identity conflicts, unknown storage and unsupported file sizes. One recovery owner remains an operational prerequisite.
- Serialize same-job repairs with a dedicated PostgreSQL advisory-lock connection, explicitly released before connection return. Never hold a job row lock while the canonical writer opens another session.
- Rehash every accepted staged file; copy only verified JSON evidence and the target PDF into a private temporary workspace. Reject unmanifested evidence, symlink paths, limits and late parsing before persistence. Derive relationships with the existing source evidence resolver.
- Bound this Preview repair to 10,000 manifest files / 8 GiB verification / 768 MiB copied metadata / 16 MiB PDF. The original accepted export has about 636 MiB of textual evidence; a read-only preflight correctly refused the initial 512 MiB allowance. The 300-second budget applies before canonical persistence; scoped SQL lock/statement timeouts apply during writes, and ambiguous outcomes reconcile from durable facts. Do not claim a hard transaction deadline or arbitrary export/provider support.
- Independently verify account and Project ownership, imported provenance, lineage and original stored bytes before existing-asset reuse. Preserve conflicting/deleted/corrupt records; fail closed.
- Append durable request/outcome facts; keep original media paths, warnings and skips as history. Canonical commit followed by lost audit must reconcile on replay and credit a repair exactly once. Replays verify persisted originals and never re-upload or double-count.
- A dedicated repair selector in the existing import modal hashes the selected original locally and matches the owner manifest. It sends identity JSON, not replacement bytes, through the existing authenticated import client. It must never invoke the original Choose File flow or clear/change the saved job pointer. Ambiguous outcomes reconcile by read-only audit lookup, without automatic resubmission.
- The client requires exactly one matching basename/size/SHA path and refuses ambiguity. Completed replays verify the retained target and owned canonical receipt without copying the whole export, adding audit facts, or crediting counters again. Deleted assets/documents, multiple matches, conflicting metadata, missing links and changed stored originals fail closed.

Proof: extraction reader/fallback and NUL-only cases; real PostgreSQL document persistence with original SHA preserved; separate-session lock contention; wrong-owner/Project, source identity/tamper/symlink/limit guards; existing corrupt/deleted media refusal; canonical success before failed audit and replay; existing generic retry still strict; route auth and private-field filtering; frontend local-hash/abort/one-POST/reconciliation/pointer tests. Run focused existing import/document/contract suites and actual frontend dependency build. Obtain independent final diff review before serving changes.

Rollout: isolated worktree from the prior reviewed import candidate. Back up and guard hashes of only changed serving files, preserve all unrelated dirty files and concurrent Guardian work. Do not restart the running account-import worker. Load the additive backend route only after review/tests and a verified narrow rollout. Use the legitimate owner UI for repair after terminal processing. Verify original downloads, source record coverage and remaining limitations; retain all archives and staging.

Candidate validation (November 16): 147 focused backend tests passed, including real disposable PostgreSQL lock/admission/replay proofs and linked owned/projectless/foreign-Project source-thread cases; 57 frontend tests passed. The production Vite build passed using existing Preview-container dependencies in a separate temporary source tree. Host typecheck reports one pre-existing `vite.config.ts` overload diagnostic, byte-identical to the parent candidate under the same compiler. Qualification generator check, registry validation and diff whitespace checks passed. Read-only preflight independently rehashed all 7,506 retained files / 5,041,377,162 bytes for each of the two failed PDFs in 45.062 and 39.226 seconds, preserving positive uploaded-file evidence and one original relationship each. These checks do not establish deployed or repaired state; final independent review and runtime receipts are separate.
